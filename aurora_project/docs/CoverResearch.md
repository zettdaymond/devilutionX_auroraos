# Research: нативная обложка плитки Lipstick (Aurora OS 5.2)

Исследование механизма обложек домашнего экрана Авроры для не-Qt приложения
(DevilutionX, SDL2). Проведено 2026-09-05 на эмуляторе AuroraOS 5.2.1.200
(x86_64). Результат: рабочая нативная обложка, паритет с системными
приложениями — коммит `c9d5b6980` (WindowSystem WIP 3); WIP 4 (стадийный)
довёл до живой карточки с прогрессом — `d0398925c`.

## Зачем

До этого плитка показывала последний буфер главного окна: наш код детектил
«мы свёрнуты» (стейтмашина на фокус/дисплей), переключал wl_buffer transform,
рисовал карточку в буфер. Нативный механизм отдает плитку композитору:
приложение держит отдельное окно-обложку, Lipstick сам показывает его в
нужный момент. Минус целый класс проблем (детект сворачивания, трансформы,
прозрачность за локскрином, GLES-смешение).

## Как устроена обложка в Aurora 5.2 (карта потребителя)

Читается сверху вниз — кто кого вызывает:

```
Silica-приложение (Qt)
  ├─ CoverWindow.qml (private) → Private.CoverWindow (C++, libsailfishsilicaplugin)
  │     — окно обложки, размер Theme.coverSize, title "_CoverWindow"
  │     — ставит "__winref:<N>" на главное окно (строка в .so)
  └─ QtWayland (libQt5WaylandClient)
        — qt_surface_extension → qt_extended_surface.update_generic_property

lipstick (композитор, liblipstick-qt5)
  ├─ серверная сторона qt_surface_extension: свойства → QWaylandSurface::windowProperties
  ├─ LipstickCompositor::windowIdForLink(siblingId, link)  [липпstickcompositor.cpp:389]
  │     — ищет окно ТОГО ЖЕ ПРОЦЕССА, чьё свойство WINID == link (uint)
  └─ LipstickCompositor::windowForId(id) — внутренние id окон

aurora-home (QML домашнего экрана, /usr/share/aurora-home/)
  ├─ WindowWrapperBase.qml — WindowProperty(SAILFISH_COVER_WINDOW) на главном окне
  │     — "__winref:N" разворачивается в coverId (windowproperty.cpp:99-106)
  ├─ WindowWrapper.qml:20 — coverHint = windowProperty("SAILFISH_HAVE_COVER")
  └─ Switcher.qml (ОТДЕЛЬНЫЙ процесс ru.auroraos.homescreen.switcher)
        — делегаты по foreign-toplevel-хэндлам; cover = windowForId(windowWrapper.coverId)
        — cover.resize(coverSize): свитчер РЕСАЙЗИТ окно обложки (configure!)
```

Ключевой вывод: линковка — по WINID-свойству обложки (uint, любое число),
привязанному строкой `__winref:<N>` на главном окне; вся трасса реактивная
(свойства обновляются на лету).

Референсы: auroraos-rs/aurora-gui (объявление механизма), форк
lmaxyz/winit@rm_maliut (рецепт set_transient для 5.2), sailfishos/lipstick
(исходники windowForLink/windowIdForLink).

## Хронология грабель (главное!)

Каждый пункт стоил цикла сборки — не повторять:

1. **UAF registry**: `wl_registry_bind` после `wl_registry_destroy` —
   краш. Биндить ДО destroy (забинженный прокси переживает смерть registry).
2. **Маршалинг new_id**: `wl_proxy_marshal_constructor` требует
   NULL-заглушку в слоте new_id, фактические аргументы — ПОСЛЕ неё.
   Без этого libwayland молча отвергает запрос («null value passed for
   arg 1»), свойства не уходят.
3. **set_transient к себе vs к главному**: приём автора winit-форка
   (`set_transient(own_surface)`) на 5.2.1.200 не сработал; рабочий
   вариант — transient к ГЛАВНОМУ окну (как у Qt). Вырожденный родитель,
   похоже, мешает lipstick создать оконный айтем вовсе.
4. **Роль окна обложки**: toplevel → поднимается отдельным окном;
   transient к главному + CATEGORY=cover ДО первого коммита → окно уходит
   в hiddenItem (JollaHomeLayout.qml:2467). Свойства ПОСЛЕ мапа не
   перекатегоризируют окно.
5. **Второй qt_extended_surface игнорируется**: свойства главного окна,
   отправленные через собственный extended surface (не созданный SDL),
   lipstick отбрасывает. Доказано зондом STATUSBAR_VISIBLE (статусбар
   появляется только через SDL-шный объект). Решение — патч SDL-форка:
   `3rdParty/SDL2/sdl-wayland-generic-property.patch` экспортирует
   `SDL_WaylandSetWindowGenericProperty` (использует wind->extended_surface).
6. **Fullscreen маскирует windowProperties**: на set_fullscreen-окне
   даже правильно доставленные свойства не действуют (тот же
   статусбар-зонд). Лаунчер временно создаётся оконным 720x1600;
   вернуть fullscreen можно только после ревизии на реальном устройстве.
7. **XRGB8888 → «спектр»**: буфер рендерился поканально разложенным
   (три изображения подряд). ARGB8888 — чисто.
8. **Пересоздание SHM-пулов → мусор**: уничтожение пула предыдущего
   кадра, пока композитор держит буфер, даёт полосы из переработанной
   памяти. Решение: один постоянный пул (memfd + mmap), кадры пишутся
   в ту же память, коммитится тот же wl_buffer.
9. **configure обязателен**: свитчер ресайзит окно обложки под карточку
   (cover.resize) — без ответа на configure плитка пуста. Контент —
   **aspect crop** (full-bleed), не fit (давало поля).
10. **Бета-эмулятора**: обложки в обычной плитке бывают выключены
    системно (у ВСЕХ приложений, включая Settings) — индикатор паритета:
    режим закрытия. Чинится перезапуском домашнего экрана.
11. **DisplayFramebufferScale офскрин-кадра** (WIP 4): с привязанным
    render target `SDL_GetRendererOutputSize` возвращает размер
    ТАРГЕТА; ImGui (SDL2-бэкенд) считает fbScale = target/window, и
    RenderDrawData молча сжимает контент в угол (карточка «чёрная»).
    Лечение: в офскрин-кадре гасить `io.DisplayFramebufferScale=(1,1)`
    вместе с подменой DisplaySize. Пока таргет совпадает с окном
    (запечка WIP 3), грабля невидима.

## Итоговый рецепт (как в NativeCover.cpp)

```
1. wl_compositor.create_surface
2. wl_shell.get_shell_surface
3. set_transient(главное_окно, 0, 0, 0); set_title("cover"); set_class(<как у main>)
4. свойства (QVariant, BE; до первого коммита):
     main (через SDL-патч!):  WINID=1, SAILFISH_HAVE_COVER=true,
                              SAILFISH_COVER_WINDOW="__winref:2"
     cover:                    WINID=2, CATEGORY="cover", TRANSPARENT=false
5. SHM: memfd → wl_shm_create_pool (жить вечно) → create_buffer(ARGB8888)
6. RGB24 → аспект-кроп → mmap; attach + damage + commit
7. listener: ping → pong (обязательно!), configure → ресайз пула + перезаливка
```

QVariant-байты: `[u32 тип BE][байт isNull][payload BE]`; типы: bool=1,
uint=3, u64=5, string=10 (UTF-16BE, длина в байтах). Совпадает байт-в-байт
с aurora-gui (aurora_app/src/q_variant_compat.rs) и Qt.

## Инструменты отладки

- `WAYLAND_DEBUG=1` — полный wayland-трейс; эталон: `jolla-settings`
  с тем же env (его окно обложки создаётся лениво, при первом
  сворачивании — видно весь рабочий диалог).
- Зонды в билде (env):
  - `DEVILUTIONX_NATIVE_COVER_DEBUG=1` — сплошной красный буфер +
    кардиограмма (перезаливка каждые 500 мс);
  - `DEVILUTIONX_NATIVE_COVER_PROBE=1` — STATUSBAR_VISIBLE=true на
    главное окно (жив ли канал свойств);
  - `DEVILUTIONX_COVER_SEQ=a|b|c` — порядок роль/свойства/мап;
  - `DEVILUTIONX_NATIVE_COVER=0` — выключить нативную обложку;
  - `DEVILUTIONX_COVER_WINDOWED=0` — вернуть fullscreen.
- Лог: `aurora-native-cover:` в launcher.log.
- root на эмуляторе: `echo defaultuser | devel-su -c '<cmd>'` (НЕ -p).

## WIP 4: стадийный рефакторинг (закрыт)

Первая попытка одним коммитом провалилась (дедлок старта, чёрный тайл);
переезд шёл мелкими стадиями, каждая проверена на устройстве:

1. `c787bbb42` — CoverMachine и буферная схема выпилены; GameCover —
   предикат видимости (флаги окна + дисплей), край переключает паузу
   аудиоустройства; паузы меню/видео/игры больше не кормят машину.
1.5. `a6373dffc` — NativeCover API под событийный цикл: `Size()`
   (размер от configure свитчера, 316x392 на эмуляторе),
   `ConfigureEventType()` + пуш SDL-события из слушателя configure.
2. `9639810c8` — блокирующий цикл обложки (`RunCoverLoop`): в плитке
   цикл спит в `SDL_WaitEvent`, CPU 0%; защёлка `m_focusKnown` от
   дедлока «FOCUS_LOST до первого кадра».
3. `d0398925c` — живая карточка: `RenderCoverPixels` рендерит офскрин
   в размере окна обложки (аспект плитки; подменяются DisplaySize и
   DisplayFramebufferScale — грабля 11), перерисовка по wake-пинкам
   стора (процент/скорость загрузки в плитке), по configure (сразу,
   ещё в видимом состоянии) и финальный кадр на выходе «Играть».
   Диагностика: `DEVILUTIONX_COVER_DUMP=1` — BMP-дампы карточек.

## Дизайн карточки (редизайн после WIP 4)

Три состояния `LauncherView::RenderCover`, тёплый уголь `IM_COL32(24,18,13)`
без фото-арта (в миниатюре плитки фотография превращается в кашу; канон
обложек Авроры просит приглушённость и читаемость). Шапку плитки (иконка +
имя) рисует композитор — внутри не дублируем.

- **Простой лаунчера** — лицо режима (лайн-арт черепа Diablo / монаха
  Hellfire, костяная тонировка 0.95): идентичность, которой нет в системной
  шапке.
- **Загрузка** — эмбер-кольцо с процентом крупным кеглем в центре (H1-акцент
  по канону Авроры; форма перекликается с iris-анимацией запуска), имя файла
  и скорость под ним. Эталонно соответствует стайлгайду: у Авроры свой
  пример «Почта отображает процесс загрузки».
- **Пауза (игра запущена)** — призрачное лицо (альфа 0.28–0.36) и дышащий
  уголёк за ним: синус ~3.5 с, яркость свечения ×1.0–×2.3, радиус
  ×0.85–×1.05, температура от глубокого красного к оранжевому, градиент —
  48 вложенных кругов (меньше — видны кольца-ступеньки; проверено
  vision-ревью). Ни слова, ни символа паузы: словарь медиаплеера не
  Diablo-словарь; состояние несут лицо и огонь — «спит, но огонь не погас».
  Пик горит ярче статики: текста на карточке нет, топить нечего (амплитуду
  поднимали дважды — в статичных кадрах робкую пульсацию глаз не выделяет;
  на живом устройстве, наоборот, может оказаться навязчивее — финальную
  громкость решаем по телефону).

Стайлгайд (developer.auroraos.ru/doc/ui_kit/cover, «Кастомная обложка»)
запрещает «частую и резкую» анимацию и допускает её «в качестве отображения
обновления контента (часы, таймер, загрузка)». Загрузка — точно норм; пауза —
серая зона по букве, чисто по духу (самое медленное гладкое движение,
приглушённые цвета, состояние осмысленное).

**Фолбэк, если стор не пустит анимацию** (решение: основа — дыхание, при
отказе возвращаемся к одной из карточек): (A) слово «ПАУЗА» Exocet Cyrillic,
кегль 0.125·MinSide, золото (0.95,0.72,0.30,0.95), призрак под ним; (B) две
золотые капсулы (w=0.055·MinSide, h=0.55·высоты лица, зазор ≈1.1·w) поверх
призрака — вариант-победитель тройного vision-ревью до дыхания.

Анимация на устройстве — решено на 2026-09-06 (телефон 5.1):

- **Сейчас карточка паузы статична**: призрак лица + слово «ПАУЗА»
  шрифтом Beaufort Bold (кириллица Exocet забракована ревью) золотом,
  умеренное тепло углей. Ставится финальным запечённым кадром на выходе
  «Играть», CPU в плитке ~0.
- **Пребечённое «дыхание» (8 фаз, таймер) опробовано и отклонено**:
  на телефоне читалось рывками — frame-колбэки композитора приходят
  лениво и рвано (статичный дом перекрашивается редко), а плотнее
  шагать = гонять SHM-мемкопи на 2–4% CPU. Живой рендер на фазе
  движка невозможен (рендерер/ImGui лаунчера умирают на выходе).
- **Цель — GPU-рендер обложки (WIP 4b, SDL-форк)**: настоящий рендер
  в окно обложки без CPU-раундтрипа, ненавязчивая анимация ~20 FPS
  со всплеском раз в ~5 с. Попутное наследие эксперимента: паузы
  движка получили GameCover::SleepWhileHidden (потребление событий
  обложки вместо возврата в очередь — возврат оживлял WaitEvent и
  крутил цикл сайта на полное ядро).

## Дорожная карта WIP 5: API окон Авроры в SDL-форке

Цель — перенести наработки в SDL: свой форк с API управления окнами
для Авроры, где механизм работает **с любым SDL-рендерером**.

Ключевой вывод: «любой рендерер» достигается не контекстными трюками
(перебинд eglMakeCurrent, `SDL_GL_SHARE_WITH_CURRENT_CONTEXT` — это
GL-only механика прикладного уровня), а рангом абстракции. Если
обложка — **настоящее SDL-окно**, то `SDL_CreateRenderer(coverWindow)`
работает с любым бекендом: GL садится на `wl_egl_window` поверхности
(GPU напрямую, без SHM/ReadPixels), software разруливается через SHM.

Эскиз API:

```
SDL_CreateCoverWindow(parent)        // или флаг к SDL_CreateWindow
  → wl_shell transient к parent (рабочая роль WIP 3)
  → qt_surface_extension нативно в wayland-бекенде:
      CATEGORY=cover/WINID на себе,
      SAILFISH_HAVE_COVER + SAILFISH_COVER_WINDOW=__winref на parent
  → configure свитчера → SDL_WINDOWEVENT_RESIZED
  → окно не получает фокус/ввод, не сидит в стеке окон
```

Приложение выкидывает ручной вейланд NativeCover — остаётся потребитель
API. Проблема ImGui/текстур при двух рендерерах (атлас шрифтов и арт
принадлежат контексту главного): предпочтительный вариант — рендерер
с шарингом контекста в форке (главный рисует офскрин-таргет, рендерер
обложки делает `RenderCopy` → present; один ImGui, общие текстуры,
ноль CPU-раундтрипа). Альтернативы: второй контекст ImGui (овекилл)
или оставить ReadPixels (для 1–2 обновлений в секунду не болит).

Риски: wayland-бекенд SDL xdg-центричен — для обложки нужна роль-ветка
wl_shell (нужность toplevel не доказана — A/B `DEVILUTIONX_WL_TOPLEVEL`);
qt_surface_extension встроить в бекенд (заготовка — экспорт
`SDL_WaylandSetWindowGenericProperty` в патче `6ab2d0aed`); свойства на
родителе работают только через SDL-шный extended surface.

Стадии (каждая = проверка на устройстве + коммит): **4a** — дизайн API +
перенос вейланд-механики NativeCover в бекенд форка, приложение на новом
API с доставкой кадров через SHM; **4b** — рендерер на окне обложки
(GL без раундтрипа, шаринг); **4c** — вычистка.
